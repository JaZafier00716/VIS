### A-04 Download uses the document name as a file path (path traversal, silent overwrite)
- Severity high · FIX (G2) · Security, Business, Data · from SEC-1, BUS-9, DATA-3 · Status fixed
- Evidence (checked): `app/business/service/DocumentService.java:88` `storage.retrieve(d.getStorageKey(), targetDir.resolve(d.getName()))`; `app/business/domain/NodeCreator.java:13-21` checks only blank and length ≤ 100; `app/data/file/FileDocumentStorage.java:24` `Files.copy(resolve(key), target, REPLACE_EXISTING)`. Menu export names come from the menu name (`MenuExportService.fileName`).
- Why high: a worker can name a document `../../.bashrc`; a colleague's download then overwrites a file outside the chosen folder (code execution on login). In normal use two documents with the same name from different folders, or an existing file, are overwritten silently while the count says all were downloaded. A NUL in a name throws an unchecked `InvalidPathException`.
- Fix: (1) `NodeCreator.createIn` rejects `/`, `\`, control characters and the names `.`/`..` ("Název nesmí obsahovat lomítka ani řídicí znaky."). (2) `downloadDocuments`: `Path target = targetDir.resolve(name).normalize()` and refuse unless `target.getParent().equals(targetDir.normalize())`; if the file exists, use a free name `name (2).ext` instead of overwriting. (3) `FileDocumentStorage.retrieve` without `REPLACE_EXISTING`. (4) `MenuExportService.fileName` replaces `/ \` too.

### A-05 Working copy of an older revision while the newest is WORKING
- Severity high · FIX (G1) · Business · from BUS-2 · Status fixed
- Evidence (checked): `app/business/domain/MenuRevision.java:159-165` `createWorkingCopy()` allowed for any non-editable revision (historical included); `app/business/service/MenuService.java:124-128` insert branch checks only `latest.getRevisionNo() != revision.getRevisionNo() - 1`, not `latest.getState()`. UI: `MenuEditorWindow.java:88` copy button in the banner of a historical revision.
- Why high: latest r3 WORKING, open r1, "Vytvořit pracovní kopii", save → r4 WORKING. r3 stays WORKING but can no longer be edited or shared; its saved work is buried. Breaks A2 UC08 "Pracovní může být vždy jen nejnovější revize menu" on a visible UI path.
- Fix: in `saveRevision` insert branch require `latest.getState() == SHARED`, else `ConflictException("Nejnovější revize je pracovní. Upravte ji, nebo ji nejprve sdílejte.")`. Also refuse earlier: `MenuService.createWorkingCopy` reads the latest header and throws the same message when the newest revision is WORKING (so the user does not edit a copy that cannot be saved).

## Medium

### A-06 Manager web session and admin check trust a cached User
- Severity medium · FIX (G3) · Security, Presentation, Business · from PRES-1, SEC-6 (session part), BUS-7 · Status fixed
- Evidence (checked): `app/presentation/web/ManagerHandler.java:123` `sessions.put(token, new Session(user, …))`; `currentUser` l.136-145 returns `s.user()` without re-check; the MANAGER check is only in `login` l.115. `app/business/service/UserService.java:62-65` `requireAdmin` tests `admin.isActiveAdmin()` on the object passed in.
- Why: a deactivated manager, or one whose MANAGER role was removed (UC16), keeps reading all projects and prices on the public web for up to 8 h. A deactivated admin keeps user management until restart.
- Fix: session stores the user id; `currentUser` re-reads it via a new `AuthService.findActiveUser(long id)` (`users.findById` + `isActive()`), and drops the session unless active and MANAGER. `requireAdmin` re-reads the actor inside the transaction (`users.findById(admin.getId())`).

### A-07 Save/share state checks are not atomic
- Severity medium · FIX (G1) · Business, Data · from BUS-3, DATA-6 (guard part) · Status fixed
- Evidence (checked): `app/data/oracle/OracleMenuMapper.java:100-113` overwrite UPDATE has no `AND state = 'WORKING'`; `updateState` l.116-119 has no state condition and does not change `created_at`; `app/business/service/SharingService.java:44-55` checks `latest` in an earlier statement and never compares `revision.getLoadedSavedAt()`.
- Why: A saves while B shares at the same moment → A rewrites a SHARED revision already linked to the customer (and its item comments go by ON DELETE CASCADE). If B overwrote the WORKING revision after A opened it, A shares B's content that A never validated.
- Fix: overwrite UPDATE adds `AND state = 'WORKING'` (0 rows → existing ConflictException path). State change: `UPDATE … SET state='SHARED' WHERE … AND state='WORKING' AND created_at = ?` (loadedSavedAt), 0 rows → ConflictException. Port method returns boolean.

### A-08 Revision object changed before the DB write
- Severity medium · FIX (G1) · Business · from BUS-1, BUS-13 · Status fixed
- Evidence (checked): `SharingService.java:53-54` `revision.markShared(); menus.updateState(revision);` inside the tx; `MenuRevision.java:168-172` `markShared()` sets SHARED and notifies listeners. `MenuService.java:122,127` `revision.recordSave(…)` before `overwriteRevision`/`insertRevision`.
- Why: if the write or the link insert fails, the DB rolls back but the editor holds a SHARED read-only revision with no link (listeners already told), or shows an unsaved timestamp.
- Fix: do the DB work with values computed locally, mutate the object only after `inTransaction` returns (as `markStored()` already does). `validate()` stays before the tx. Together with A-07 the mapper call takes `(menuId, revisionNo, loadedSavedAt)` instead of the mutated object.

### A-09 DB column limits not validated in business
- Severity medium · FIX (G1) · Business · from BUS-5 · Status fixed
- Evidence: `db/01_schema.sql:224` `menu_categories.name VARCHAR2(60)`, `:237-239` `quantity NUMBER(8,2)`, `unit_price NUMBER(10,2)`, `note VARCHAR2(200)`; `products.current_price NUMBER(10,2)`; `users.full_name 100`, `email 254`. `MenuRevision.addCategory` checks only blank/duplicate; `findProblems` only `quantity>0`, `price>=0`; `Product.update` no upper limit; `User.create` no length checks.
- Why: a 61-char category, note > 200, quantity ≥ 1 000 000 or price ≥ 100 000 000 fail inside save with ORA-12899/01438 instead of the UC08 6.2 "highlight the faulty item" flow. Quantity 0.004 passes `signum()>0`, is stored as 0.00 and violates the CHECK; 0.005 becomes 0.01 so the total changes after reload.
- Fix: `findProblems` adds category name ≤ 60, note ≤ 200, quantity scale ≤ 2 and < 1 000 000, unit price scale ≤ 2 and < 100 000 000; `Product` price < 100 000 000 and scale ≤ 2; `User.create` full name ≤ 100, e-mail ≤ 254. Czech messages via the existing problem list / field errors.
